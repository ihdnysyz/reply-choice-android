# 一加 13 手工验证清单

当前只有一个可用 QQ 发送账号。首轮 QQ 5 次回调 / 5 次正文可读已经收到用户确认；不再要求重复该测试，也不把单账号测试解释成联系人身份稳定性证明。微信尚未测试。

## 0.2.1-alpha 首次试用

1. 安装更新后打开“回话”，确认通知使用权与监听服务状态。应用内的 QQ 和“开始接入记录”开关需重新开启；微信暂时关闭。
2. 进入“设置”，填写自己可用的 Chat Completions 兼容 HTTPS 完整接口地址、精确模型 ID，在手机上输入 API Key。DeepSeek 用户可点“使用 DeepSeek 官方接口”补齐路径。不要把 Key 发到聊天、截图或仓库。
3. 阅读实际接收域名与上传说明，开启“同意云端生成”。在“生成”页输入虚构消息“今晚方便聊一下吗？”，选择“未知”关系，点“生成三条回复”。应出现三条完整且不重复的候选；选一条复制，确认剪贴板内容正确。无联网、401、429、超时及输出格式错误应明确显示失败。
4. 先保持“QQ 新通知自动生成”关闭。让现有 QQ 测试账号发一条虚构文字，在“记录”页选中此条，进入“生成”页并选择本次关系。只用该条内容生成，不应带入之前的通知或关系。
5. 再主动开启“QQ 新通知自动生成”，按系统提示授权本应用发通知。让测试账号发另一条虚构文字，查看是否出现不含消息正文的“已有三条回复建议”通知；点开应到建议页。身份未确认时所有自动请求应按“未知关系”处理。
6. 点击“尝试打开原聊天”，确认是否进入正确聊天；该入口可能失效，不能把点击等同于已发送。回复必须由用户粘贴、核对并自行发送。
7. 生成过程中关闭“同意云端生成”或暂停通知接入，旧结果不得出现。建议超过 10 分钟后应过期；删除 API Key 后不得继续发请求。
8. 到诊断页复制报告，核对没有消息正文、真实姓名、API Key 或通知键。QQ 通知是否能稳定区分两个联系人仍无法用单账号验证。

仅用虚构文字测试。当前自动处理只面向 QQ；群聊来源可能无法从通知中区分，自动开关应在用户了解此限制后再开启。数据仅在本机内存短期保存，模型服务商对已收到请求的处理以其条款为准。
